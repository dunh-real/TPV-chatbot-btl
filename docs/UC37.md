# UC37 — Theo dõi tác vụ và quản lý sản phẩm AI

## Phạm vi đã triển khai

- Danh sách có phân trang, lọc loại/trạng thái/khoảng thời gian; hiển thị agent, tiến độ và thời gian.
- Chi tiết có kết quả, phiên bản đầu ra, mẫu/phiên bản mẫu và tài liệu nguồn đã ghi nhận.
- Chạy nền cho soát, tóm tắt, trích nhiệm vụ, soạn/tổng hợp báo cáo và tạo slide. Các workflow cũ được ghi nhận vào cùng sổ tác vụ.
- Chạy lại tác vụ lỗi bằng một tác vụ mới có `RetryOfTaskId`; giữ nguyên lịch sử lần chạy cũ, chống gửi chạy lại trùng khi còn lần chạy đang hoạt động.
- Xóa mềm sản phẩm, phiên bản và liên kết nguồn; giữ tác vụ và nhật ký. Bản gốc nguồn vẫn có thể tải theo quyền tác vụ. Không xóa vật lý object MinIO vì có thể còn được tham chiếu.
- Người dùng bật thông báo cho từng tác vụ hoặc mặc định cho các lần chạy sau. Giao diện thăm dò mỗi 5 giây, hiển thị số chưa đọc trên menu, thông báo nổi khi hoàn thành/lỗi và liên kết mở kết quả. Đây là thông báo trong ứng dụng; không gửi email hay thông báo hệ điều hành.

## Luồng và nơi lưu dữ liệu

```text
frontend/js/tasks.js → POST /api/tasks
    → kiểm tra quyền + tham số → lưu nguồn vào MinIO
    → AI_Tasks: Queued
worker trong lifespan FastAPI → khóa SQL → Processing + lease
    → tra lại tài khoản/quyền → tải nguồn vào thư mục tạm
    → workflow hiện có → file kết quả vào MinIO
    → sản phẩm SQL + AI_OutputVersions + AI_SourceReferences
    → Completed hoặc Failed + AI_ExecutionLogs
giao diện → GET danh sách/chi tiết/thông báo → tải file qua API có kiểm quyền
```

SQLite vẫn chỉ dùng pháp lý. Không tạo bảng, không đổi schema MSSQL, không chuyển dữ liệu cũ. Các bảng dùng lại: `AI_Tasks`, `AI_ExecutionLogs`, `AI_OutputVersions`, `AI_SourceReferences`, các bảng sản phẩm, `AI_ReportTemplate` và `AI_TemplateVersions`.

Worker sử dụng khóa MSSQL để nhiều tiến trình không nhận trùng một tác vụ. Heartbeat gia hạn lease; tác vụ mất lease chuyển `Failed`, không tự chạy lại vì lần chạy cũ có thể đã tạo tác dụng phụ. Tiến trình hết lease không được ghi đè kết quả. File tạm được dọn sau chạy; nguồn MinIO được giữ để chạy lại.

## Quyền

- `Ai.AiTask`: xem module và lịch sử của mình, tạo tác vụ nền.
- `Ai.AiTask.ViewAll`: xem tác vụ trong cùng tenant.
- `Ai.AiTask.Delete`: xóa đầu ra của mình; quản trị có thể xóa trong phạm vi được phép.
- Tạo/chạy lại/thực thi còn phải có quyền nghiệp vụ tương ứng: `Ai.DocumentReview`, `Ai.Summarize`, `Ai.TaskExtract`, `Ai.ReportDrafting`, `Ai.ReportSummary.Create`, `Ai.Slide.Create`.
- Xem toàn bộ không tự cấp quyền xóa đầu ra của người khác. Mọi API vẫn giới hạn tenant. Nguồn trong kho tri thức kiểm tra thêm quyền đọc tài liệu hiện hành.

## API và cách thử

Mở `/docs`, chọn nhóm `tasks-uc37`. Dùng cơ chế danh tính hiện tại của hệ thống; khi bật tin cậy header, gửi `X-User-Id` của tài khoản ERP và `X-Tenant-Id` đúng đơn vị.

1. Upload bằng `POST /api/agent/upload`, lấy `file_id`.
2. Tạo tác vụ:

```json
{
  "kind": "Summarize",
  "parameters": {"file_id": "upload:ten-file.docx"},
  "notify_on_finish": true
}
```

3. API trả `202` với `task_id`. Theo dõi `GET /api/tasks/{id}` hoặc mở `/ui/#tasks/{id}`. Với báo cáo/slide, `parameters` dùng schema các API nghiệp vụ hiện có (`request`, `inputs`; soạn từ file thêm `nguon: "tai_lieu"`, `file_id`).
4. Thử các API sau bằng đúng chủ tác vụ; đổi tài khoản để kiểm tra cách ly.

| API | Chức năng |
|---|---|
| `GET /api/tasks` | Lọc `page`, `page_size`, `status`, `kind`, `since`, `until` |
| `GET /api/tasks/{id}` | Chi tiết, phiên bản, mẫu và nguồn |
| `GET /api/tasks/{id}/result?version_id=...` | File hoặc JSON kết quả; bỏ version_id lấy kết quả hiện tại |
| `GET /api/tasks/{id}/source` | File tải lên ban đầu |
| `GET /api/tasks/{id}/template` | File mẫu đúng phiên bản đã dùng |
| `POST /api/tasks/{id}/retry` | Chạy lại tác vụ lỗi |
| `DELETE /api/tasks/{id}/output` | Xóa mềm đầu ra |
| `PATCH /api/tasks/{id}/notify` | Body `{"enabled":true}` |
| `GET /api/tasks/notifications` | Danh sách thông báo riêng |
| `PATCH /api/tasks/notifications/{id}/read` | Đánh dấu đã đọc |

Tác vụ cũ thiếu file nguồn hoặc tham số không thể khôi phục sẽ không cho chạy lại. Nguồn/mẫu/phiên bản chỉ hiển thị khi lần chạy đã lưu liên kết; không tự suy đoán dữ liệu lịch sử. Chạy lại tạo phiên bản đầu ra của lần chạy mới, không ghi đè phiên bản của lần cũ.

## Vận hành và kiểm thử

Khởi động backend bằng lệnh hiện tại sau khi cấu hình `AI_DATABASE_URL`, `ERP_DATABASE_URL` và MinIO. Mặc định worker chạy cùng backend; không cần Redis hoặc service mới.

```dotenv
TASK_WORKER_ENABLED=true
TASK_WORKER_POLL_SECONDS=2
TASK_LEASE_SECONDS=120
TASK_EXECUTION_TIMEOUT_SECONDS=1800
```

Các kiểm thử chạy từ `backend/`, sử dụng Python/môi trường ảo của dự án:

```bash
TASK_WORKER_ENABLED=false python -m pytest tests/test_uc37.py -q
UC37_UI_TEST=1 TASK_WORKER_ENABLED=false python -m pytest tests/test_uc37_ui.py -q
python scripts/check_uc37.py --user-id 407 --output ../artifacts/uc37/mssql-validation.json
```

Kiểm thử UI cần Playwright và Chrome (`UC37_BROWSER` đổi channel nếu cần). Kiểm thử đơn vị dùng DB bộ nhớ và giả lập dịch vụ ngoài để kiểm chứng API/điều phối; không đánh giá chất lượng LLM. Script MSSQL tạo riêng bản ghi thử có `origin=probe`, kiểm tra nhận đồng thời/lease/chạy lại/thông báo/xóa mềm rồi dọn trong `finally`; worker thường không lấy các bản ghi này.
